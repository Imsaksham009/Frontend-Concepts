## What Is OOP and Why Does It Exist?

Before writing a single line of code, let's understand the **problem OOP solves**.

As programs grow larger, code becomes harder to manage. Functions and variables scattered everywhere with no structure leads to what developers call "spaghetti code" — everything is connected to everything, changing one thing breaks ten others, and nobody can reason about the system as a whole.

OOP is a way of **organizing code around data and the things that operate on that data**, bundled together into self-contained units called **objects**. Instead of having a `getUserName()` function floating somewhere and a `userAge` variable somewhere else, you have a `User` object that owns both its data and the functions that work on it.

JavaScript's OOP is unique because it's built on **prototypes**, not classical inheritance like Java or C++. ES6 classes are beautiful syntax on top of that prototype system — but the engine is still doing prototype-based delegation underneath. Understanding this makes you dangerous in interviews, because most people treat classes as magic boxes.

---

## The Four Pillars of OOP

Every OOP language implements four core concepts. Let's establish what they mean before implementing them:

**Encapsulation** — Bundling data and the methods that operate on that data together, and restricting direct access to internal state. The outside world interacts through a controlled interface.

**Abstraction** — Hiding complex implementation details and exposing only what's necessary. Users of your class don't need to know *how* it works, only *what* it does.

**Inheritance** — A class can derive properties and methods from another class, reusing and extending existing behavior without duplicating code.

**Polymorphism** — Different classes can be treated through the same interface, each implementing it differently. One interface, many implementations.

We'll implement all four thoroughly. Let's begin.

## ES6 Classes — The Complete Syntax

### The Basic Class

```javascript
class Person {
    // constructor — called automatically when 'new' is used
    // sets up the instance's own properties
    constructor(name, age) {
        this.name = name; // public instance property
        this.age  = age;
    }
    
    // Instance method — lives on Person.prototype
    // shared by ALL instances, not copied onto each one
    greet() {
        return `Hi, I'm ${this.name} and I'm ${this.age}`;
    }
    
    // Another instance method
    haveBirthday() {
        this.age++;
        return `Happy birthday ${this.name}! Now ${this.age}`;
    }
}

// Creating instances
const peter = new Person('Peter Parker', 25);
const tony  = new Person('Tony Stark', 45);

peter.greet(); // "Hi, I'm Peter Parker and I'm 25"
tony.greet();  // "Hi, I'm Tony Stark and I'm 45"

// Methods are on the prototype — shared, not copied
console.log(peter.greet === tony.greet); // true — same function!
console.log(peter.name === tony.name);   // false — own properties

// Under the hood — still prototype based
console.log(Object.getPrototypeOf(peter) === Person.prototype); // true
```

### The Class is Just a Function

This is crucial to internalize. Under the hood, the `class` keyword creates a function:

```javascript
class Person {
    constructor(name) { this.name = name; }
    greet() { return `Hi ${this.name}`; }
}

// Under the hood, roughly equivalent to:
function Person(name) { this.name = name; }
Person.prototype.greet = function() { return `Hi ${this.name}`; };

// Proof
console.log(typeof Person); // 'function' — a class IS a function
```

## Getters and Setters

Getters and setters let you define computed properties and intercept property access with custom logic:

```javascript
class Temperature {
    constructor(celsius) {
        this._celsius = celsius; // convention: _ means "treat as private"
    }
    
    // Getter — accessed like a property, not called like a method
    get fahrenheit() {
        return this._celsius * 9/5 + 32;
    }
    
    get celsius() {
        return this._celsius;
    }
    
    // Setter — intercepts assignment
    set celsius(value) {
        if (value < -273.15) {
            throw new RangeError('Temperature below absolute zero');
        }
        this._celsius = value;
    }
    
    set fahrenheit(value) {
        this.celsius = (value - 32) * 5/9; // uses the celsius setter for validation
    }
}

const temp = new Temperature(100);

// Accessed like properties — no parentheses
console.log(temp.fahrenheit); // 212
console.log(temp.celsius);    // 100

// Assigned like properties
temp.celsius = 0;
console.log(temp.fahrenheit); // 32

temp.fahrenheit = 98.6;
console.log(temp.celsius);    // 37

// Validation triggers
temp.celsius = -300; // RangeError: Temperature below absolute zero
```

### Getters and Setters for Computed Properties

```javascript
class FullName {
    constructor(firstName, lastName) {
        this.firstName = firstName;
        this.lastName  = lastName;
    }
    
    get fullName() {
        return `${this.firstName} ${this.lastName}`;
    }
    
    set fullName(value) {
        const parts = value.split(' ');
        if (parts.length !== 2) {
            throw new Error('Full name must be two words');
        }
        this.firstName = parts[0];
        this.lastName  = parts[1];
    }
}

const person = new FullName('Peter', 'Parker');
console.log(person.fullName); // 'Peter Parker'

person.fullName = 'Tony Stark';
console.log(person.firstName); // 'Tony'
console.log(person.lastName);  // 'Stark'
```

## Static Methods and Properties

Static members belong to the **class itself**, not to instances. You call them on the class, not on objects created from the class:

```javascript
class MathUtils {
    // Static property — belongs to the class
    static PI = 3.14159265358979;
    
    // Static method — utility function that doesn't need instance data
    static add(a, b)      { return a + b; }
    static subtract(a, b) { return a - b; }
    static multiply(a, b) { return a * b; }
    
    static circleArea(radius) {
        return MathUtils.PI * radius ** 2;
    }
    
    static randomBetween(min, max) {
        return Math.floor(Math.random() * (max - min + 1)) + min;
    }
}

// Called on the CLASS, not on instances
MathUtils.add(5, 3);           // 8
MathUtils.circleArea(5);       // 78.539...
MathUtils.randomBetween(1, 10); // random 1-10

// Cannot call on instances
const math = new MathUtils();
math.add(5, 3); // TypeError: math.add is not a function
```

### Static Factory Methods — A Very Common Pattern

A static factory method is an alternative to using `new` directly. It gives you more control over object creation:

```javascript
class User {
    constructor(name, email, role) {
        this.name  = name;
        this.email = email;
        this.role  = role;
        this.createdAt = new Date();
    }
    
    // Static factory methods — named constructors
    static createAdmin(name, email) {
        return new User(name, email, 'admin');
    }
    
    static createGuest() {
        return new User('Guest', 'guest@temp.com', 'guest');
    }
    
    static fromJSON(json) {
        const data = JSON.parse(json);
        return new User(data.name, data.email, data.role);
    }
    
    // Static validation
    static isValidEmail(email) {
        return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
    }
}

const admin = User.createAdmin('Peter', 'peter@example.com');
const guest = User.createGuest();
const fromData = User.fromJSON('{"name":"Tony","email":"tony@stark.com","role":"user"}');

User.isValidEmail('peter@example.com'); // true
User.isValidEmail('not-an-email');      // false
```

## Public, Private, and Protected Fields

This is where modern JavaScript OOP gets really powerful. ES2022 introduced **true private fields** using the `#` syntax.

### Public Fields

```javascript
class Person {
    // Public field declaration — optional but good practice
    // Same as setting in constructor
    species = 'Human'; // public field with default value
    
    constructor(name) {
        this.name = name; // public field set in constructor
    }
}

const peter = new Person('Peter');
console.log(peter.species); // 'Human'
console.log(peter.name);    // 'Peter'
peter.species = 'Mutant';   // can be changed from outside
```

### Private Fields with `#`

Private fields are **truly private** — not just by convention. The engine enforces it at the language level. No way to access them from outside the class:

```javascript
class BankAccount {
    // Private fields — TRULY inaccessible from outside
    #balance;
    #owner;
    #transactionHistory = []; // private with default value
    #pin;
    
    constructor(owner, initialBalance, pin) {
        this.#owner   = owner;
        this.#balance = initialBalance;
        this.#pin     = pin;
    }
    
    // Public interface — controlled access to private data
    deposit(amount) {
        if (amount <= 0) throw new Error('Deposit must be positive');
        this.#balance += amount;
        this.#recordTransaction('deposit', amount);
        return this; // for chaining
    }
    
    withdraw(amount, pin) {
        this.#validatePin(pin);
        if (amount > this.#balance) throw new Error('Insufficient funds');
        this.#balance -= amount;
        this.#recordTransaction('withdrawal', amount);
        return this;
    }
    
    getBalance(pin) {
        this.#validatePin(pin);
        return this.#balance;
    }
    
    getStatement() {
        return [...this.#transactionHistory]; // return copy
    }
    
    // Private methods — internal helpers, not exposed
    #validatePin(pin) {
        if (pin !== this.#pin) throw new Error('Invalid PIN');
    }
    
    #recordTransaction(type, amount) {
        this.#transactionHistory.push({
            type,
            amount,
            balance: this.#balance,
            date: new Date()
        });
    }
}

const account = new BankAccount('Peter', 1000, 1234);

// Public interface works
account.deposit(500);
account.withdraw(200, 1234);
console.log(account.getBalance(1234)); // 1300

// Private fields are completely inaccessible
console.log(account.#balance);        // SyntaxError: Private field '#balance'
console.log(account['#balance']);      // undefined — doesn't work either
console.log(account.#pin);            // SyntaxError

// Wrong PIN throws
account.getBalance(9999); // Error: Invalid PIN
```

### Private Static Fields and Methods

```javascript
class IdGenerator {
    static #nextId = 1; // private static field
    
    static #validate(id) { // private static method
        return typeof id === 'number' && id > 0;
    }
    
    static generate() {
        return IdGenerator.#nextId++;
    }
    
    static reset() {
        IdGenerator.#nextId = 1;
    }
}

IdGenerator.generate(); // 1
IdGenerator.generate(); // 2
IdGenerator.generate(); // 3
IdGenerator.reset();
IdGenerator.generate(); // 1 again

// Private static not accessible outside
IdGenerator.#nextId; // SyntaxError
```

### The "Protected" Convention

JavaScript has no true `protected` keyword. The convention is to prefix with a single underscore `_` to signal "don't touch this from outside, but subclasses can":

```javascript
class Animal {
    #name; // truly private
    _sound; // "protected" by convention — subclasses can access
    
    constructor(name, sound) {
        this.#name  = name;
        this._sound = sound; // subclasses can use this
    }
    
    getName() { return this.#name; }
    
    speak() {
        return `${this.#name} says ${this._sound}`;
    }
}

class Dog extends Animal {
    constructor(name) {
        super(name, 'woof');
    }
    
    // Can access _sound (protected convention)
    barkLoudly() {
        return this._sound.toUpperCase() + '!!!';
    }
    
    // Cannot access #name (truly private to Animal)
    // this.#name would be SyntaxError
}
```

## Inheritance — `extends` and `super`

### Basic Inheritance

```javascript
class Animal {
    #name;
    #age;
    
    constructor(name, age) {
        this.#name = name;
        this.#age  = age;
    }
    
    get name() { return this.#name; }
    get age()  { return this.#age;  }
    
    speak() {
        return `${this.#name} makes a sound`;
    }
    
    describe() {
        return `${this.#name} is ${this.#age} years old`;
    }
    
    toString() {
        return `Animal(${this.#name})`;
    }
}

class Dog extends Animal {
    #breed;
    
    constructor(name, age, breed) {
        // super() MUST be called before accessing 'this'
        // It runs the parent constructor, setting up parent's state
        super(name, age);
        this.#breed = breed; // then set child's own state
    }
    
    get breed() { return this.#breed; }
    
    // New method — only on Dog
    fetch(item) {
        return `${this.name} fetches the ${item}!`;
    }
    
    // Method overriding — Dog has its own speak()
    speak() {
        return `${this.name} barks: WOOF!`;
    }
    
    // Extending parent method using super
    describe() {
        // super.method() calls the PARENT's version of the method
        const parentDesc = super.describe();
        return `${parentDesc}, breed: ${this.#breed}`;
    }
}

const rex = new Dog('Rex', 3, 'Labrador');

rex.speak();    // 'Rex barks: WOOF!' — Dog's version
rex.describe(); // 'Rex is 3 years old, breed: Labrador' — extended
rex.fetch('ball'); // 'Rex fetches the ball!'

// Inheritance chain verification
console.log(rex instanceof Dog);    // true
console.log(rex instanceof Animal); // true
console.log(rex instanceof Object); // true
```

### `super` in Depth

`super` has two distinct uses:

```javascript
class Vehicle {
    #make;
    #model;
    #year;
    static #count = 0;
    
    constructor(make, model, year) {
        this.#make  = make;
        this.#model = model;
        this.#year  = year;
        Vehicle.#count++;
    }
    
    get make()  { return this.#make;  }
    get model() { return this.#model; }
    get year()  { return this.#year;  }
    
    static getCount() { return Vehicle.#count; }
    
    describe() {
        return `${this.#year} ${this.#make} ${this.#model}`;
    }
    
    static compare(v1, v2) {
        return v1.year - v2.year;
    }
}

class ElectricVehicle extends Vehicle {
    #batteryCapacity;
    #range;
    
    constructor(make, model, year, batteryCapacity, range) {
        // Use 1: super() as constructor call
        // Must be FIRST statement — before any 'this' access
        super(make, model, year);
        
        this.#batteryCapacity = batteryCapacity;
        this.#range           = range;
    }
    
    // Use 2: super.method() to call parent instance method
    describe() {
        const base = super.describe(); // calls Vehicle.describe()
        return `${base} (Electric, ${this.#range}mi range)`;
    }
    
    // Accessing parent static method
    static compareRange(ev1, ev2) {
        return ev1.range - ev2.range;
    }
    
    get range() { return this.#range; }
    get batteryCapacity() { return this.#batteryCapacity; }
    
    charge(hours) {
        const charged = hours * 50; // 50 miles per hour charging
        return `Charged ${Math.min(charged, this.#range)} miles`;
    }
}

class HybridVehicle extends Vehicle {
    #fuelType;
    #mpg;
    
    constructor(make, model, year, fuelType, mpg) {
        super(make, model, year);
        this.#fuelType = fuelType;
        this.#mpg      = mpg;
    }
    
    describe() {
        return `${super.describe()} (Hybrid, ${this.#mpg}mpg)`;
    }
}

const tesla   = new ElectricVehicle('Tesla', 'Model 3', 2023, 75, 358);
const prius   = new HybridVehicle('Toyota', 'Prius', 2023, 'Gasoline', 52);
const regular = new Vehicle('Honda', 'Civic', 2022);

tesla.describe();  // '2023 Tesla Model 3 (Electric, 358mi range)'
prius.describe();  // '2023 Toyota Prius (Hybrid, 52mpg)'

// Static method from parent accessible on child
Vehicle.getCount(); // 3 — all three vehicles counted
```

## The Four OOP Pillars — Full Implementation

### Pillar 1 — Encapsulation

Bundling data and methods, restricting direct access:

```javascript
class ShoppingCart {
    #items = [];
    #discountCode = null;
    #discounts = {
        'SAVE10': 0.10,
        'SAVE20': 0.20,
        'HALFOFF': 0.50
    };
    
    // Public interface — controlled way to interact with private data
    addItem(product, quantity = 1) {
        const existing = this.#items.find(i => i.product.id === product.id);
        
        if (existing) {
            existing.quantity += quantity;
        } else {
            this.#items.push({ product, quantity });
        }
        
        return this; // chainable
    }
    
    removeItem(productId) {
        this.#items = this.#items.filter(i => i.product.id !== productId);
        return this;
    }
    
    applyDiscount(code) {
        if (!this.#discounts[code]) {
            throw new Error('Invalid discount code');
        }
        this.#discountCode = code;
        return this;
    }
    
    get subtotal() {
        return this.#items.reduce((sum, item) => {
            return sum + (item.product.price * item.quantity);
        }, 0);
    }
    
    get discount() {
        if (!this.#discountCode) return 0;
        return this.subtotal * this.#discounts[this.#discountCode];
    }
    
    get total() {
        return this.subtotal - this.discount;
    }
    
    get itemCount() {
        return this.#items.reduce((sum, item) => sum + item.quantity, 0);
    }
    
    // Controlled read access — returns copy so original can't be mutated
    getItems() {
        return this.#items.map(item => ({ ...item }));
    }
    
    checkout() {
        if (this.#items.length === 0) {
            throw new Error('Cart is empty');
        }
        const order = {
            items: this.getItems(),
            subtotal: this.subtotal,
            discount: this.discount,
            total: this.total,
            date: new Date()
        };
        this.#items = []; // clear cart after checkout
        this.#discountCode = null;
        return order;
    }
}

const cart = new ShoppingCart();

cart
    .addItem({ id: 1, name: 'Laptop', price: 999 }, 1)
    .addItem({ id: 2, name: 'Mouse',  price: 29  }, 2)
    .applyDiscount('SAVE10');

console.log(cart.subtotal);   // 1057
console.log(cart.discount);   // 105.7
console.log(cart.total);      // 951.3
console.log(cart.itemCount);  // 3

// Cannot access private data directly
console.log(cart.#items); // SyntaxError
```

### Pillar 2 — Abstraction

Hiding complexity, exposing only what's needed:

```javascript
class DatabaseConnection {
    #host;
    #port;
    #database;
    #connection = null;
    #queryCount = 0;
    #isConnected = false;
    
    constructor(config) {
        this.#host     = config.host;
        this.#port     = config.port;
        this.#database = config.database;
    }
    
    // Public interface — simple and clean
    // Users don't need to know HOW connection is established
    async connect() {
        await this.#establishConnection();
        await this.#authenticate();
        await this.#selectDatabase();
        this.#isConnected = true;
        console.log('Connected successfully');
    }
    
    async query(sql, params = []) {
        this.#ensureConnected();
        this.#validateQuery(sql);
        const sanitized = this.#sanitizeParams(params);
        this.#queryCount++;
        return await this.#executeQuery(sql, sanitized);
    }
    
    async disconnect() {
        await this.#closeConnection();
        this.#isConnected = false;
    }
    
    get stats() {
        return { queries: this.#queryCount, connected: this.#isConnected };
    }
    
    // Private implementation details — completely hidden
    async #establishConnection() {
        // Complex TCP connection logic hidden here
        this.#connection = `connected to ${this.#host}:${this.#port}`;
    }
    
    async #authenticate() {
        // Authentication logic hidden here
    }
    
    async #selectDatabase() {
        // Database selection logic hidden here
    }
    
    #ensureConnected() {
        if (!this.#isConnected) throw new Error('Not connected');
    }
    
    #validateQuery(sql) {
        if (!sql || typeof sql !== 'string') {
            throw new Error('Invalid query');
        }
    }
    
    #sanitizeParams(params) {
        // SQL injection prevention — complex but hidden from user
        return params.map(p => typeof p === 'string' ? p.replace(/'/g, "''") : p);
    }
    
    async #executeQuery(sql, params) {
        // Actual query execution hidden here
        return { rows: [], count: 0 };
    }
    
    async #closeConnection() {
        this.#connection = null;
    }
}

// User only sees the simple public interface
const db = new DatabaseConnection({
    host: 'localhost',
    port: 5432,
    database: 'myapp'
});

// Clean, simple usage — all complexity is abstracted away
await db.connect();
const users = await db.query('SELECT * FROM users WHERE age > ?', [18]);
await db.disconnect();
```

### Pillar 3 — Inheritance

Reusing and extending behavior:

```javascript
class UIComponent {
    #id;
    #element = null;
    #eventListeners = new Map();
    
    constructor(id) {
        this.#id = id;
    }
    
    get id() { return this.#id; }
    
    // Template method pattern — defines skeleton, subclasses fill in details
    render(container) {
        this.#element = this.createElement(); // abstract — subclass implements
        this.applyStyles(this.#element);      // can be overridden
        this.bindEvents(this.#element);       // can be overridden
        container.appendChild(this.#element);
        return this;
    }
    
    // To be overridden by subclasses
    createElement() {
        throw new Error(`${this.constructor.name} must implement createElement()`);
    }
    
    applyStyles(element) {
        element.id = this.#id; // default implementation
    }
    
    bindEvents(element) {} // default — no events
    
    on(event, handler) {
        this.#eventListeners.set(event, handler);
        this.#element?.addEventListener(event, handler);
        return this;
    }
    
    destroy() {
        this.#eventListeners.forEach((handler, event) => {
            this.#element?.removeEventListener(event, handler);
        });
        this.#element?.remove();
        this.#element = null;
    }
    
    get element() { return this.#element; }
}

class Button extends UIComponent {
    #label;
    #variant;
    
    constructor(id, label, variant = 'primary') {
        super(id);
        this.#label   = label;
        this.#variant = variant;
    }
    
    // Implement abstract method
    createElement() {
        const btn = document.createElement('button');
        btn.textContent = this.#label;
        return btn;
    }
    
    // Override parent method
    applyStyles(element) {
        super.applyStyles(element); // call parent's implementation
        element.className = `btn btn-${this.#variant}`;
    }
    
    setLabel(label) {
        this.#label = label;
        if (this.element) this.element.textContent = label;
        return this;
    }
}

class Input extends UIComponent {
    #placeholder;
    #type;
    #value = '';
    
    constructor(id, placeholder, type = 'text') {
        super(id);
        this.#placeholder = placeholder;
        this.#type        = type;
    }
    
    createElement() {
        const input = document.createElement('input');
        input.type        = this.#type;
        input.placeholder = this.#placeholder;
        return input;
    }
    
    bindEvents(element) {
        element.addEventListener('input', (e) => {
            this.#value = e.target.value;
        });
    }
    
    get value() { return this.#value; }
}

// Usage
const btn   = new Button('submit-btn', 'Submit', 'primary');
```

### Pillar 4 — Polymorphism

Different classes responding to the same interface differently:

```javascript
// Base class defines the interface
class Shape {
    #color;
    
    constructor(color = 'black') {
        this.#color = color;
    }
    
    get color() { return this.#color; }
    
    // Each subclass MUST implement these
    area() {
        throw new Error(`${this.constructor.name} must implement area()`);
    }
    
    perimeter() {
        throw new Error(`${this.constructor.name} must implement perimeter()`);
    }
    
    // Shared behavior — uses polymorphic methods
    describe() {
        return `${this.constructor.name}: area=${this.area().toFixed(2)}, ` +
               `perimeter=${this.perimeter().toFixed(2)}, color=${this.#color}`;
    }
    
    // Polymorphic comparison
    isLargerThan(otherShape) {
        return this.area() > otherShape.area();
    }
}

class Circle extends Shape {
    #radius;
    
    constructor(radius, color) {
        super(color);
        this.#radius = radius;
    }
    
    area()      { return Math.PI * this.#radius ** 2; }
    perimeter() { return 2 * Math.PI * this.#radius;  }
    
    get radius() { return this.#radius; }
}

class Rectangle extends Shape {
    #width;
    #height;
    
    constructor(width, height, color) {
        super(color);
        this.#width  = width;
        this.#height = height;
    }
    
    area()      { return this.#width * this.#height;            }
    perimeter() { return 2 * (this.#width + this.#height);      }
}

class Triangle extends Shape {
    #a; #b; #c; // three sides
    
    constructor(a, b, c, color) {
        super(color);
        if (a + b <= c || b + c <= a || a + c <= b) {
            throw new Error('Invalid triangle sides');
        }
        this.#a = a; this.#b = b; this.#c = c;
    }
    
    perimeter() { return this.#a + this.#b + this.#c; }
    
    area() {
        // Heron's formula
        const s = this.perimeter() / 2;
        return Math.sqrt(s * (s-this.#a) * (s-this.#b) * (s-this.#c));
    }
}

// POLYMORPHISM IN ACTION
// Same function works on ANY shape — it doesn't need to know the type
function printShapeInfo(shape) {
    console.log(shape.describe());
}

function totalArea(shapes) {
    // Calls .area() on each — each implements it differently
    return shapes.reduce((sum, shape) => sum + shape.area(), 0);
}

function largestShape(shapes) {
    return shapes.reduce((largest, shape) =>
        shape.isLargerThan(largest) ? shape : largest
    );
}

const shapes = [
    new Circle(5, 'red'),
    new Rectangle(4, 6, 'blue'),
    new Triangle(3, 4, 5, 'green'),
    new Circle(3, 'yellow')
];

// Same function, different behavior for each shape
shapes.forEach(printShapeInfo);
// Circle: area=78.54, perimeter=31.42, color=red
// Rectangle: area=24.00, perimeter=20.00, color=blue
// Triangle: area=6.00, perimeter=12.00, color=green
// Circle: area=28.27, perimeter=18.85, color=yellow

console.log('Total area:', totalArea(shapes).toFixed(2));    // 136.81
console.log('Largest:', largestShape(shapes).describe());    // Circle(r=5)
```

## Abstract Classes Pattern

JavaScript doesn't have the `abstract` keyword, but we can implement the pattern:

```javascript
class AbstractRepository {
    constructor() {
        // Prevent direct instantiation of abstract class
        if (new.target === AbstractRepository) {
            throw new Error('AbstractRepository cannot be instantiated directly');
        }
    }
    
    // Abstract methods — subclasses MUST implement
    async findById(id) {
        throw new Error('findById() must be implemented');
    }
    
    async findAll() {
        throw new Error('findAll() must be implemented');
    }
    
    async save(entity) {
        throw new Error('save() must be implemented');
    }
    
    async delete(id) {
        throw new Error('delete() must be implemented');
    }
    
    // Concrete methods — shared by all subclasses
    async findOrFail(id) {
        const entity = await this.findById(id);
        if (!entity) throw new Error(`Entity ${id} not found`);
        return entity;
    }
    
    async saveAll(entities) {
        return Promise.all(entities.map(e => this.save(e)));
    }
}

// Concrete implementation
class UserRepository extends AbstractRepository {
    #db = new Map(); // simulating database
    
    async findById(id) {
        return this.#db.get(id) || null;
    }
    
    async findAll() {
        return [...this.#db.values()];
    }
    
    async save(user) {
        this.#db.set(user.id, user);
        return user;
    }
    
    async delete(id) {
        return this.#db.delete(id);
    }
    
    // Additional user-specific methods
    async findByEmail(email) {
        const users = await this.findAll();
        return users.find(u => u.email === email);
    }
}

// Cannot instantiate abstract class directly
new AbstractRepository(); // Error: AbstractRepository cannot be instantiated directly

// Can instantiate concrete class
const userRepo = new UserRepository();
await userRepo.save({ id: 1, name: 'Peter', email: 'peter@example.com' });
const user = await userRepo.findOrFail(1); // uses concrete method from abstract class
```

## Method Overriding and Polymorphism

```javascript
class Logger {
    #prefix;
    
    constructor(prefix = '') {
        this.#prefix = prefix;
    }
    
    // Can be overridden
    formatMessage(level, message) {
        const timestamp = new Date().toISOString();
        return `[${timestamp}] [${level}] ${this.#prefix}${message}`;
    }
    
    log(message)   { console.log(this.formatMessage('LOG',   message)); }
    warn(message)  { console.warn(this.formatMessage('WARN',  message)); }
    error(message) { console.error(this.formatMessage('ERROR', message)); }
}

class JSONLogger extends Logger {
    // Override formatMessage — different format, same interface
    formatMessage(level, message) {
        return JSON.stringify({
            timestamp: new Date().toISOString(),
            level,
            message
        });
    }
}

class ColorLogger extends Logger {
    #colors = {
        LOG:   '\x1b[32m', // green
        WARN:  '\x1b[33m', // yellow
        ERROR: '\x1b[31m'  // red
    };
    
    formatMessage(level, message) {
        const reset = '\x1b[0m';
        const color = this.#colors[level];
        // Call parent's formatMessage and add color
        return `${color}${super.formatMessage(level, message)}${reset}`;
    }
}

// All three loggers have the same interface
// But produce completely different output — polymorphism
const loggers = [
    new Logger('App: '),
    new JSONLogger(),
    new ColorLogger('Dev: ')
];

loggers.forEach(logger => logger.error('Something went wrong'));
```

## Mixins — Multiple Inheritance Pattern

JavaScript classes can only extend **one** parent. But sometimes you need behaviors from multiple sources. Mixins solve this:

```javascript
// Mixins are functions that take a class and return an extended class
const Serializable = (Base) => class extends Base {
    serialize() {
        return JSON.stringify(this);
    }
    
    static deserialize(json) {
        return Object.assign(new this(), JSON.parse(json));
    }
};

const Validatable = (Base) => class extends Base {
    #errors = [];
    
    validate() {
        this.#errors = [];
        
        // Each class can define its own validation rules
        if (this.validationRules) {
            this.validationRules().forEach(rule => {
                const error = rule(this);
                if (error) this.#errors.push(error);
            });
        }
        
        return this.#errors.length === 0;
    }
    
    get errors() { return [...this.#errors]; }
};

const Timestamped = (Base) => class extends Base {
    #createdAt = new Date();
    #updatedAt = new Date();
    
    get createdAt() { return this.#createdAt; }
    get updatedAt() { return this.#updatedAt; }
    
    touch() {
        this.#updatedAt = new Date();
        return this;
    }
};

const Eventable = (Base) => class extends Base {
    #listeners = new Map();
    
    on(event, handler) {
        if (!this.#listeners.has(event)) {
            this.#listeners.set(event, []);
        }
        this.#listeners.get(event).push(handler);
        return this;
    }
    
    emit(event, data) {
        (this.#listeners.get(event) || []).forEach(handler => handler(data));
        return this;
    }
    
    off(event, handler) {
        const handlers = this.#listeners.get(event) || [];
        this.#listeners.set(event, handlers.filter(h => h !== handler));
        return this;
    }
};

// Base class
class Entity {
    constructor(id) {
        this.id = id;
    }
}

// Apply multiple mixins — compose behaviors
class User extends Serializable(Validatable(Timestamped(Eventable(Entity)))) {
    #name;
    #email;
    
    constructor(id, name, email) {
        super(id);
        this.#name  = name;
        this.#email = email;
    }
    
    get name()  { return this.#name;  }
    get email() { return this.#email; }
    
    // Define validation rules for this class
    validationRules() {
        return [
            (user) => !user.name  ? 'Name is required'  : null,
            (user) => !user.email ? 'Email is required' : null,
            (user) => !user.email?.includes('@') ? 'Invalid email' : null,
        ];
    }
    
    updateEmail(email) {
        this.#email = email;
        this.touch();              // from Timestamped
        this.emit('updated', this); // from Eventable
        return this;
    }
}

const user = new User(1, 'Peter', 'peter@example.com');

// Has ALL mixin behaviors
console.log(user.validate());    // true — from Validatable
console.log(user.createdAt);     // Date — from Timestamped
console.log(user.serialize());   // JSON string — from Serializable

user.on('updated', (u) => console.log(`User updated: ${u.name}`)); // from Eventable
user.updateEmail('new@email.com'); // emits 'updated'
```

## The Complete OOP Mental Model

Here is the unified picture of OOP in JavaScript:

**Classes** are blueprints — they define structure and behavior. The `constructor` sets up each instance's own private state. Methods defined in the class body go on the prototype, shared by all instances.

**Private fields** (`#field`) are enforced by the engine — truly inaccessible from outside. This is real encapsulation, not just convention.

**Inheritance** via `extends` sets up the prototype chain automatically. `super()` in the constructor runs the parent's constructor. `super.method()` calls the parent's version of a method.

**The four pillars** are not separate features — they're design goals achieved through the language mechanics:
- **Encapsulation** — private fields + public interface
- **Abstraction** — hiding complexity behind simple methods
- **Inheritance** — `extends` + `super`
- **Polymorphism** — method overriding + consistent interfaces

**Mixins** solve the multiple inheritance problem by composing behaviors through function-based class extension.

And underneath all of this — it's still prototypes. Classes are a clean syntax over the prototype chain we learned earlier. Every method call still traverses that chain. Every `instanceof` check still walks it. The foundation never changed — we just got better tools to work with it.
